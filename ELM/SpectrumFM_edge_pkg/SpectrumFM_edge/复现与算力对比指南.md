# SpectrumFM AMC 复现 + 端侧/服务器算力对比指南

本包用于在**端侧设备**上复现 SpectrumFM 的 AMC（自动调制识别）实验，并与**服务器**做初步算力对比。

---

## 1. 目标

在端侧设备上跑通与服务器**完全相同**的 AMC 微调 + 评估流程，记录：

- **训练算力**：微调（`amc.py`）每 epoch 耗时 / 总耗时、早停轮数；
- **推理算力**：单样本延迟（batch=1）、吞吐量（batch=256）；
- **精度**：OA / Precision / Recall / F1（应与服务器一致，用于确认流程正确）。

对比基准 = 服务器的实测值（见第 7 节）。

## 5. 三步实验（都在 `code/` 目录下运行）

> ⚠️ 所有命令**必须先 `cd code/`**，代码里用相对路径读 `Data/`、`Checkpoint/`、写 `Results/`。

### 步骤 1：微调（算力对比核心）

```bash
cd code
python amc.py
```

- 默认 `--epochs 100`，早停 patience=10（服务器 32 epoch 早停）。若端侧太慢，可先试 `python amc.py --epochs 5` 估时间。
- 流程：`process_data()` 预处理（Python 循环归一化，**服务器约 1-3 分钟，端侧更久，无输出属正常**）→ 逐 epoch 训练 + 验证 → 早停 → 分 SNR 结果 + 混淆矩阵。
- **关键记录**：
  - 每 epoch 的训练/验证耗时（从日志 `Epoch [i/100]` 的时间戳算）；
  - 总训练墙钟时间（到早停为止）；
  - 早停轮数、最终 TestAcc。
- 输出文件：
  - 最优模型 `Checkpoint/amc/Our.pt`（会**覆盖**打包进来的服务器版本，若想保留先备份）；
  - `Results/amc/snr_results.csv`（分 SNR 准确率）；
  - `Confusion_matrix/amc/Our_*.csv`（各 SNR 混淆矩阵）。

### 步骤 2：评估（精度 + 推理）

```bash
python eval.py
```

- 打印总体 OA / Precision / Recall / F1，并对照论文 TABLE III（Precision 0.7529 / Recall 0.6372 / F1 0.6620）。
- **关键记录**：四项指标值、评估总耗时。

### 步骤 3：效率测量（需 CUDA）

```bash
python profile_model.py --name <设备名> --f1 <步骤2的实测F1>
```

- 输出：参数量、FLOPs、batch=1 延迟、batch=256 吞吐、显存峰值等，追加到 `Results/profiling/benchmark.csv`。
- **注意**：此脚本用 `torch.cuda.Event` 计时，**纯 CPU 设备跑不了**。若端侧是 CPU-only，跳过本步，改用手动计时（如 `time python eval.py`）作为推理算力参考。

## 8. 已知坑（已处理的 + 需注意的）

1. **map_location（已处理）**：本包代码里的 `torch.load` 已统一加 `map_location="cpu"`，纯 CPU 设备也能加载权重。改动 3 处文件：`Model/model.py`（预训练权重）、`eval.py`、`amc.py`（test/test_per_snr/confusion 三处）。
2. **torch ≥ 2.6 的 `weights_only=True` 默认值**：本仓库权重都是纯 `state_dict`（全 tensor），可正常加载，无需改。
3. **必须 `cd code/` 再运行**：相对路径依赖 cwd。
4. **微调会覆盖 `Checkpoint/amc/Our.pt`**：如需保留服务器版本先 `cp` 备份。
5. **`amc.py` 顶部 import 了若干用不到的 baseline 模型**（`Model/AMC_model.py` 的 ResNet/VGG 等）和 `torchsummary`/`seaborn`/`matplotlib`，别删 import；装上依赖即可，不影响运行。
6. **`num_workers` 参数**：代码里 DataLoader 实际没传 `num_workers`，忽略即可。
7. **`process_data()` 预处理较慢**：Python 循环做 iq2ap + min-max 归一化，端侧 CPU 弱时会明显更久，耐心等，日志无输出属正常。
8. **`profile_model.py` 需 CUDA**：纯 CPU 设备跳过或用 `time python eval.py` 替代计时。
